# #308 PR2 — UI du panier Chronodrive sur `/courses` : plan d'implémentation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Sur `/courses`, une carte « Panier Chronodrive » permet de lancer la demande de panier, en suit l'état et affiche le dernier compte-rendu. Elle n'apparaît que si un exécuteur est enregistré pour le foyer.

**Architecture:**
- Toute la logique d'affichage vit dans un module **pur**, `lib/panier-affichage.ts` (état, libellés, pluriels, message d'échec), testé en Vitest.
- Un module client, `lib/panier-client.ts`, lit l'état par la RPC `etat_panier()` (client navigateur, RLS) et lance la demande par `POST /api/panier/demande`, socle livré en PR1.
- Le composant `components/courses/panier-chronodrive.tsx` assemble les deux. Il interroge le serveur toutes les 10 s **seulement** pendant une demande active, et relit l'état au retour sur l'onglet.
- Pas de canal Realtime ni de nouvelle table : RG-84, décision du grilling.

**Tech Stack:** Next.js 16 (client component), Tailwind v4 (tokens de `app/globals.css`), `lucide-react`, `sonner` (toasts), Vitest + Testing Library, Playwright (staging).

**Spec:** `SPECS_FONCTIONNELLES.md` US-53, RG-81, RG-83, RG-84 (« Affichage »), §5.8 ; `PRODUCT.md`, `DESIGN.md` ; issue #308, section « Découpage et décisions ». Règles : `.claude/rules/ui.md`, `courses-cycle.md`, `chronodrive.md`, `next-react.md`, `e2e.md`.

**Branche :** `feat/308-ui-panier`, depuis `main` à jour (PR1 mergée, `fca3f80`).

## Global Constraints

- Tout en français, tutoiement. Dans le texte JSX, apostrophe typographique `’`. Les commentaires citent les RG.
- Couleurs :
  - vert = action : bouton principal `bg-primary` / `hover:bg-primary-hover`, texte blanc, `rounded-full` ;
  - `amber-*` = échec ou prudence, jamais l'accent terracotta ;
  - jamais `bg-white` : `bg-surface` ;
  - contraste ≥ 4.5:1 en clair **et** en sombre.
- Carte : `rounded-lg border border-brand-100 bg-surface p-4 shadow-sm`. Titre de carte en `h2`, police de corps, `text-lg font-bold text-brand-900`, jamais `font-display`.
- Icônes `lucide-react` uniquement, sans emoji ni glyphe Unicode. `ShoppingBasket` pour la carte (`ShoppingCart` est pris par la nav), `Loader2` pour l'attente (`motion-safe:animate-spin`).
- Feedback `transition active:scale-[0.97] motion-reduce:active:scale-100` sur le bouton ; zone tactile ≥ 44 px (`after:-inset-1`, comme les boutons de l'en-tête).
- Bouton visible **seulement si** `etat.executeur === true` (RG-81).
- La carte n'est montée que sur le **cycle courant** : `cycle.ancre === ancreParDefaut(new Date(), jourCourses)`. Pourquoi : la demande vise toujours le cycle courant (règle `chronodrive.md`, « POST /api/panier/demande ne lit aucun corps »).
- Le compte-rendu affiché est celui de `derniere` **seulement si** `derniere.ancre === cycle.ancre`.
- Une demande active (`en_attente` / `en_cours`) désactive le bouton, quelle que soit son ancre (une seule demande active par foyer, RG-83).
- Interrogation : toutes les **10 000 ms**, seulement si la dernière demande est `en_attente` ou `en_cours`. Relecture immédiate sur `visibilitychange` → `visible`. Les intervalles sont nettoyés au démontage.
- Libellés exacts :
  - bouton disponible : `Constituer mon panier Chronodrive` ;
  - bouton pendant une demande active : `Panier en cours…`, plus la ligne `Lancé à <HH h MM>` (heure de `cree_le`, fuseau Europe/Paris, ex. `Lancé à 18 h 05`) ;
  - résumé : `<n> ajouté(s) · <n> à choisir · <n> introuvable(s)` (accords : `1 ajouté`, `2 ajoutés`, `1 introuvable`, `2 introuvables`, `à choisir` invariable) ;
  - sections du rapport : `À choisir toi-même`, `Introuvables`, `Ajoutés au panier` (cette dernière repliée par défaut) ;
  - `Rappel : rien n’est commandé. Relis et valide ton panier dans l’appli Chronodrive.` sous le résumé (RG-82) ;
  - toast de succès : `C’est parti : ton panier se remplit.` ;
  - en cas d'échec de la requête, le toast reprend le message d'erreur renvoyé par la route (`parseApiError`).
- Messages d'échec par cause (`motif_echec` est déjà en français lisible) :
  - `injoignable` → `Ton exécuteur n’a pas répondu (<motif>).` ;
  - `non_prise` et `delai_depasse` → `<motif>` tel quel ;
  - `executeur` → `Ton exécuteur a signalé un problème : <motif>`.
  - Si le motif est absent → `Le panier n’a pas pu être constitué.`
- Rapport tardif (`rapport_tardif: true`) : petite mention `Compte-rendu arrivé après le délai.` en `text-xs text-brand-700/85`.
- Aucune écriture localStorage : l'état vit en mémoire du composant (pas de store partagé).
- Ne pas casser le markup verrouillé par `e2e/courses.spec.ts` : la carte est **hors** des `<section>` de catégories et hors du `<header>` (règle `courses-cycle.md`).

## Review Focus

1. **Un membre sans exécuteur, ou un autre foyer.** La carte ne doit rien rendre : ni bouton, ni titre, ni espace réservé. Test : Task 3, `aucun exécuteur → rien n’est rendu` ; Task 4 e2e, compte B.
2. **Une demande lancée par un autre membre, ou par l'assistant (#320).** Le bouton doit passer en `Panier en cours…` au plus tard au prochain retour sur l'onglet ou au tick suivant, sans recharger. Test : Task 3, `relit l’état au retour sur l’onglet` et `interroge pendant une demande active`.
3. **Double tap sur le bouton.** Une seule requête doit partir : le bouton est désactivé dès le clic, avant la réponse. Test : Task 3, `double clic → une seule requête`.
4. **Un cycle passé ou futur affiché.** La carte ne doit pas apparaître, et aucun rapport d'un autre cycle ne doit être montré. Test : Task 3, `cycle non courant → rien` et `rapport d’un autre cycle masqué`.
5. **Lecture de l'état qui échoue** (réseau coupé en magasin). Aucun crash ni écran rouge. La carte garde son dernier état connu ; au premier chargement, elle ne s'affiche pas. L'erreur est loggée (`console.error`), sans toast répété à chaque tick. Test : Task 3, `échec de lecture → log, pas de toast répété`.

- Produces :
  - `chargerEtatPanier(supabase: ClientSupabase = clientParDefaut()): Promise<EtatPanier>` : appelle `rpc("etat_panier")` et lève sur erreur. Elle ne doit pas avaler l'erreur (Review Focus 5 : c'est l'appelant qui logge).
