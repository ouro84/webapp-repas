## Défaut : « haricots verts » en double quantité

L'article OMQ « haricots verts », quantité « 800 g », a été ajouté en **2** paquets de « Haricots verts extra-fins » (AUCHAN, contenance « 1 kg », id 4407, proposé par le cache). Un seul paquet suffisait.

Cause : le LLM a envoyé `quantite: 2`. Les gardes de l'outil portaient sur le produit (proposé pour le terme, disponible), aucune sur la quantité.

Correctif (branche `feat/308-executeur`) :

- **Plafond déterministe** : chaque ligne de `ajouter_au_panier` porte `quantite_omq`, la quantité OMQ de l'article. `src/quantites.ts` la lit avec la contenance du produit en masse, volume ou nombre ; dans la même dimension, la quantité envoyée vaut `min(demande, ceil(omq / contenance))`, au moins 1. Le code ne l'augmente jamais, et ne fait rien quand les unités ne se comparent pas (cuillères, sachet, botte, vide).
- **Résultat** : `demande` est la quantité envoyée ; `quantiteAjustee: {demandee, envoyee}` signale le plafond.
- **Articles fusionnés** : la skill passe leurs quantités jointes par « + » (« 2 c.à.s + 160 g ») ; une part illisible annule le plafond.
- **Skill** : `quantite_omq` sur chaque ligne, ligne « quantités ajustées » dans le message Telegram.

## Verdict d'Arnaud

- Une erreur de quantité (haricots verts, 800 g → 2 × 1 kg), corrigée par le plafond ci-dessus.
- « lentilles (boîte) » → « Lentilles vertes 500 g » (sèches) : **accepté**. Chronodrive ne vend pas de lentilles en conserve ; Arnaud les achète ailleurs.
