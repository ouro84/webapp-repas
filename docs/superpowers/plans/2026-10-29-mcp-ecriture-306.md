# #306 — Outils MCP d'écriture + article d'aide : plan d'implémentation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal :** un assistant connecté à OMQ (OAuth, #305) peut générer le cycle, remplacer un repas, changer le nombre de personnes, ajouter une recette du foyer, ajouter un article à la liste et cocher un article, avec la même sémantique que l'UI ; l'article d'aide « Connecter OMQ à votre assistant IA » est publié dans `/aide`.

**Architecture :** chaque outil vit dans `lib/mcp/ecriture-*.ts`, reçoit le client « par jeton » (RLS `mon_foyer()`, RG-71) et **compose** les services existants (`genererPourUtilisateur`, `sauvegarderCycleDistant`, `sauvegarderSlotsDistant`, `remplacerSlot`, `remplacerSlotManuel`, `modifierPersonnes`, `creerRecette`, écritures de coches et d'articles manuels), rendus injectables sans changer le web. Les écritures passent par les mêmes RPC / tables que l'UI : temps réel et alerte US-21 viennent sans code dédié (RG-79). Une migration solde les deux dettes de #304 (recettes hors foyer dans les slots, ancre-date impossible).

**Tech Stack :** Next.js 16, `mcp-handler` 2.3 (SDK MCP v2), zod, Supabase (PL/pgSQL `SECURITY DEFINER`), Vitest, Playwright contre staging, API REST Notion.

**Spec :** issue #306 (épopée #302) ; `SPECS_FONCTIONNELLES.md` US-52, RG-74→79 (et RG-04, RG-13, RG-15, RG-16, RG-62, US-21, RG-32) ; `ADR.md` ADR-11 ; `.claude/rules/mcp.md`.

## Global Constraints

- Code, commentaires, messages d'erreur et descriptions d'outils **en français** ; commentaires citant les `RG-xx` / `US-xx`. Outils en `snake_case` français.
- **Jamais de `service_role` sur le chemin MCP** (RG-71). Chaque outil reçoit `creerClientParJeton(jeton)` via `executer()` ; jamais `clientParDefaut()` côté serveur.
- Fonctions d'accès rendues injectables : dernier paramètre `supabase: ClientSupabase = clientParDefaut()`. **Les appels web existants ne changent pas.**
- Date du jour côté serveur = `aujourdhuiParis()`.
- Repas = `date` (AAAA-MM-JJ) + `creneau` (`midi` | `soir`), plage −12/+6 semaines (`semaineDansPlage`).
- Erreur attendue = `ErreurOutil` (français, dit quoi faire ensuite). Une ambiguïté n'est **pas** une erreur : résultat normal `{ modifie: false, candidats }`, rien n'est écrit.
- Contrat d'outil modifié → description de l'outil modifiée dans `lib/mcp/serveur.ts`.
- Migration : `revoke execute … from public` **et** `from anon`, `grant … to authenticated` ; test SQL en transaction annulée.
- Interdits : `npm run test:e2e` en local (prod) ; `git stash` (WIP #111 dans `stash@{0}`) ; toucher à #303.
- Toute action prod (migration manuelle, variable Vercel, merge) est soumise à Arnaud avec l'ordre exact des opérations.
- Commits `type: description (#306)` terminés par `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
